board-api는 단위 테스트보다 HTTP까지 포함한 통합 테스트가 핵심입니다. 실제 TCP 포트를 열지 않고, 메모리 SQLite + Router::oneshot으로 핸들러·서비스·DB를 한 번에 검증합니다.

Rust를 처음 접한다면 — 테스트 종류

종류이 프로젝트 예검증 범위
단위 테스트fn validate_... (없음)함수 하나
통합 테스트tests/api.rs, tests/web.rs라우터 + 서비스 + DB
E2E(없음)실제 브라우저·포트

#[cfg(test)] 모듈은 같은 파일 안에 둘 수 있고, tests/*.rs는 별도 crate로 board_api를 import합니다 (01편 lib/bin 구조와 연결).

왜 lib.rs + tests/ 인가

  • main.rs — 서버만 실행
  • lib.rs — routes, db, state export
  • tests/*.rs — 외부 integration test crate가 board_api를 dependency로 사용

JUnit에서 @SpringBootTest로 전체 컨텍스트를 띄우는 것과 비슷하지만, 여기서는 Axum Router만 조립합니다.

공통 test_app()

tests/api.rs / tests/web.rs 동일 패턴:

async fn test_app() -> Router {
    let db: DatabaseConnection = db::connect("sqlite::memory:")
        .await
        .expect("in-memory database");
    db::init_schema(&db)
        .await
        .expect("schema initialization");

    Router::new()
        .merge(routes::router())
        .with_state(AppState { db })
}
선택이유
sqlite::memory:테스트마다 깨끗한 DB, 파일 잔여 없음
init_schemaposts 테이블 보장
merge(routes::router())프로덕션과 동일 라우트

tower::ServiceExt::oneshot

let create = app
    .clone()
    .oneshot(
        Request::builder()
            .method("POST")
            .uri("/api/posts")
            .header("content-type", "application/json")
            .body(Body::from(json!({ ... }).to_string()))
            .unwrap(),
    )
    .await
    .unwrap();

assert_eq!(create.status(), StatusCode::OK);
  • app.clone() — Router는 clone 가능 (내부 Arc)
  • oneshot — 요청 하나 보내고 응답 수신 (소켓 없음)
  • http_body_util::BodyExt::collect — body 바이트 수집

tests/api.rs — REST crud_flow

순서:

  3. PUT 수정 → title 변경 확인

모두 통과하면 REST·HTML 경로가 계획대로 연결된 상태입니다.

헷갈리기 쉬운 점

  • 포트를 열지 않음 — cargo test가 3000번을 쓰지 않습니다. oneshot이 메모리 안에서 HTTP만 흉내 냅니다.
  • 테스트 병렬 실행 — 기본적으로 여러 테스트가 동시에 돌 수 있습니다. 각 테스트가 자기 sqlite::memory: DB를 쓰므로 충돌하지 않습니다.
  • unwrap() in tests — 테스트 코드에서는 “실패하면 즉시 패닉”이 읽기 쉬워서 허용되는 편입니다. 프로덕션 main의 expect와 비슷한 성격입니다.

심화: 더 견고한 테스트로 가기

  • assert_json_include! 대신 필드별 assert — 현재는 created["title"] 등 핵심만 검사합니다. 스냅샷 테스트(insta)는 응답 전체 회귀에 유리합니다.
  • 웹 테스트 — HTML 전체 대신 contains("Hello")만 검사합니다. 깨지기 쉬운 UI 문구보다 비즈니스 결과(제목 노출)에 집중한 선택입니다.
  • 테스트 전용 App — test_app()을 lib의 #[cfg(test)] helper로 빼면 중복을 줄일 수 있습니다.
